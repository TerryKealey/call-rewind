# Scout product-gap submission (Call Rewind)

OneList stopped 2026-06-30. New gaps → **Scout**. Call Rewind drafts; the SE posts.

## When to draft

Only when the call shows a real **Shopify platform capability gap** that blocked a merchant need — not a partner bug, not "merchant needs training," not a missing app recommendation alone.

## How the SE submits

1. Copy the `scoutMessage` block (starts with `@Scout`).
2. Either DM it to Scout, or paste and tag `@Scout` in the internal thread discussing the gap.
3. Check Scout's reading of **Want / Why / Product / Merchant** before confirming the save.
4. Optionally run `product-gap-tracker` first for Scout / GSD / OneList-history de-dup.
5. Keep `scoutImpactInternal` (PBR / $) in chat only — never paste dollars or other merchants into Scout.

## Message template

```text
@Scout

Want: [Outcome the merchant wants — unmet intent, not "Shopify should add X"]
Why: [What breaks today and why it matters now — ≤2 sentences]
Product: [Specific Shopify product area]
Merchant: [Name], shop ID [id] or [store].myshopify.com (or "prospect, no shop yet")

Merchant-stated context: […]
Deal context: [Won / Lost / Open], [stage], [segment]. Competitor if named.
Status: [Blocker / At Risk / Already Lost / Expansion blocked / Unknown]
Workaround checked: […]
Pattern: [counts only if known; else "unknown — single call"]
Related: [existing Scout / GSD / OneList history if known; else "not checked"]
Evidence: [call date/title]; [public Help/dev links if any]
```

## Impact (chat only)

```text
Impact (chat only, not part of the Scout message)
- This deal: [Won / Lost / Open], PBR $[amount] (or "PBR unverified" / Lending note)
- Deal link: [CRM link]
```

Never auto-post from the skill or Quick site.
